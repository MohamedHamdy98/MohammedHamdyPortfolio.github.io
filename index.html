01 / shrwdbrand intelligence

Shrwd — AI Brand-Intelligence & Social-Listening Platform

A brand-intelligence SaaS that profiles a brand, tracks its media coverage, generates strategy and on-brand creative, and lets users explore everything through a chat assistant. I designed and built its 8 AI microservices.

product flow
brand site→brand profile→media coverage→strategy→creative→shrwdy chat
what I built
Brand analysis

Crawls the brand's website (httpx, with a Playwright fallback for bot-protected sites) and extracts logos, colors, fonts, and an LLM-built brand profile.

Media monitoring

Discovers media coverage with LLM query planning, search fallbacks, and deterministic relevance scoring, so results stay explainable.

Strategy generation

Turns brand and media data into a strategy, using structured outputs checked for schema, language, length, and allowed numbers.

Creative generation

Brief → platform-specific posts → Gemini images, reviewed by a vision-QA loop; logo, Arabic typography, and QR codes are composed in code.

Shrwdy assistant

Three LangGraph ReAct agents (analytics, strategy, creative editing) with SSE streaming, human-in-the-loop approvals, and short- and long-term memory.

Metric explanations (RAG)

Hybrid BM25 + embedding retrieval with RRF fusion and a local cross-encoder reranker, evaluated offline with hit@k and MRR.

engineering highlights
  • Read-only SQL tools over row-level-scoped views, with the user identity injected server-side, so the model can never query another user's data
  • Guardrails without extra LLM calls: PII redaction with reversible placeholders, prompt-injection isolation, and validators that reject invented numbers and retry
  • Fully editable designs with version history and restore
  • Per-request cost accounting (tokens, images, search, speech), Gemini context caching, and cross-pod cancellation via Postgres NOTIFY
  • Every service Dockerized and shipped with GitHub Actions CI/CD to staging and production

SyntraAI — AI Compliance Analysis & Agentic Analytics

The analysis engine behind GlassHub's compliance product. It checks audit evidence against regulatory controls, compares compliance frameworks across organizations, and answers natural-language questions over compliance data, in English and Arabic.

text-to-sql agent
router→planner→sql_gen→validate→execute→repair→answer
what I built
Compliance analysis

Reviews evidence files (PDF, images, Excel) against a control's requirements with Qwen vision/text LLMs and returns bilingual EN/AR assessments.

Reports

Generates PDF, Excel, and Markdown compliance reports and stores them on Alibaba Cloud OSS.

Text-to-SQL agent

A 7-node LangGraph graph with a safety validator that re-checks every repaired query, a bounded repair budget, and graceful out-of-scope handling.

Master Agent

Compares compliance frameworks with exact → name → semantic matching, and harmonizes frameworks across organizations with lineage preserved.

Heatmap assistant

Answers questions on the Compliance Exposure Map, classifying data vs. chat and writing SQL scoped to the dashboard's active filters.

Vision cache

A PostgreSQL page/document cache with a file fallback that avoids paying twice for the same vision-LLM analysis.

engineering highlights
  • Multi-organization harmonization pipeline: deterministic matching, embedding similarity, then LLM consolidation and validation, with tunable concurrency and token budgets
  • Langfuse tracing on every endpoint and structured Loki logs with X-User-ID / X-Request-ID request tracing
  • Loki recording rules feeding Prometheus metrics into incident and SLA Grafana dashboards
  • Shipped in Docker with a GitHub Actions → GitOps pipeline to Kubernetes

03 / cstregtech

CST — AI Regulatory Compliance Agents

An AI agent platform for regulators and the enterprises they license. It turns Arabic/English regulations into auditable controls, then audits organizations against those controls.

regulation to audit
regulation→extract_terms→controls→hybrid_rag→evidence→audit
what I built
Regulator & Enterprise APIs

Separate API domains for regulators and enterprises (licenses & organizations), each with admin, data, main-process, and chat routers.

Terms & controls

Extracts regulatory terms from Word/PDF regulations and generates structured audit controls with clause-level instructions and language detection.

Regulatory knowledge base

Chunking, multilingual embeddings, and FAISS, with hybrid semantic + BM25 retrieval and metadata filters by company and criteria.

Vision compliance reports

Compliance chatbots

OCR pipeline

PyMuPDF and Tesseract OCR to read scanned regulations and evidence before they reach the models.

  • Arabic and English output with a translation fallback
  • Prometheus instrumentation with custom per-endpoint metrics
  • Docker, NGINX path-based routing, and GitHub Actions staging/production pipelines, later migrated to Kubernetes

04 / glasshub-platformmlops

GlassHub Platform — Kubernetes GitOps, LLM Gateway & Model Serving

The infrastructure under GlassHub's AI products. I moved 5 Docker Compose projects (~17 containers) from a single VM to K3s on Azure, managed entirely through Git, and built the LLM layer the products share.

deploy flow
git push→actions→image→gitops_repo→argocd→k3s
what I built
GitOps with ArgoCD

App-of-apps pattern: one root Application bootstraps 14 child Applications with automated sync, prune, and self-heal.

Helm charts

A chart per service: Deployments with HPA, Ingress, and probes, plus a StatefulSet + PVC for the Postgres cache, with staging and production values.

Build-once CI/CD

Staging builds one image; production verifies it exists and bumps its tag in the GitOps repo with yq, with no manual helm or kubectl.

Security

Sealed Secrets stored in Git and default-deny NetworkPolicies, behind a single ingress-nginx endpoint with path-based routing.

Observability stack

kube-prometheus-stack, Loki + Promtail, and self-hosted Langfuse (ClickHouse, Valkey, cert-manager), ordered with ArgoCD sync waves.

LLM gateway & serving

LLM Cipher, an API-key-protected gateway in front of self-hosted Qwen vision and text models on vLLM + FlashAttention.

engineering highlights
  • Debugged live-cluster issues and fixed each in code: CRD sync failures (Server-Side Apply), Grafana OOMKills, a datasource CrashLoopBackOff, and a Promtail DNS mismatch
  • Products can switch models or providers through the gateway without code changes
  • Multi-stage, non-root Docker images and automated GPU setup scripts
  • Documented the platform in 7 operational runbooks and an architecture doc set
